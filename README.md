# AIエンジニアの設計演習 ── 見積支援AIをどこまで任せるか

基礎から学ぶ方は[教科書「AIエンジニアのための業務システム設計入門」](TEXTBOOK.md)から始めてください。このページでは、教科書で扱う設計判断を演習できます。

**最初の問い**　営業担当の葵さんが「北斗社に製品Pを10台売りたい。見積をお願い」と入力しました。AIがすぐに実行してよい作業を一つ、確認を待つ作業を一つ書いてください。

対象は、生成AIを使ったことがあり、業務アプリの設計を学びたい人です。紙かテキストエディターがあれば取り組めます。各問で自分の判断を一文書いてから解答例に進んでください。最後に、試験導入の可否を説明する設計メモが完成します。

## 1　何ができたら業務上の成功か

葵さんは毎回、価格表を探し、適用条件を確かめ、見積を下書きしています。時間がかかるのは価格と根拠をそろえる作業です。顧客に送付する前には営業担当の承認が必要です。

**演習**　初回リリースの機能を一つ選びます。今の仕事と比べる指標を一つ、短時間で完了しても失敗と判定する条件を一つ決めてください。

**解答例**　製品・数量・顧客を入力すると、出典と有効日付きの下書きが出る。同じ難度の案件で、入力開始から営業担当が内容を確認し終えるまでの時間を現行手順と比較する。旧価格の提示は、作成が何秒で終わっても失敗と数える。金額の乗算は通常のプログラムで確定させ、モデルには依頼文からの項目抽出と説明文の作成を任せる。下書きで時間を短縮できるかを先に確かめるため、初回の対象はここまででよい。

## 2　モデルにどの文書を読ませるか

RAG（検索拡張生成）は、質問に関係する資料を取り出し、モデルに渡して回答を作る仕組みです。今日は11月20日。下表は演習用の架空資料で、金額はすべて税別です。

| 文書 | 製品Pの単価 | 適用条件 | 閲覧範囲 |
| --- | ---: | --- | --- |
| A　標準価格表・旧版 | 900円 | 10月31日まで | 営業全員 |
| B　標準価格表・現行版 | 1,000円 | 11月1日から | 営業全員 |
| C　南社向け特約 | 800円 | 南社のみ、11月中 | 南社担当のみ |

**演習**　葵さんは北斗社担当です。最初の問いへの下書きを一行で書いてください。次に、検索でAしか返らなかったときの動作を書いてください。

**解答例**　「北斗社向け、製品P 10台、税別10,000円。根拠は標準価格表B（11月1日適用開始）。」検索範囲を利用者の閲覧権限で絞り、適用先と日付を確認してからモデルに渡す。Aしか見つからない場合は金額を保留し、現行表の所在を確認する。Cはモデルへの入力にも含めない。

**切り分け問題**　誤答が9,000円だった。検索記録にAしかない場合は、まずBの取り込みと有効日の絞り込みを調べる。Bだけを渡した記録がある場合は、抽出した単価、数量、計算結果、表示文を順に照合する。同じ誤答でも、最初に直す箇所が変わる。

## 3　一度だけ登録したことをどう確かめるか

下書きが役立つと分かり、次に「承認した見積を登録する」機能を試します。モデルが外部の業務機能を呼び出す仕組みをツール呼び出しといいます。次は架空の実行記録です。

| 時刻 | 記録 |
| --- | --- |
| 10時00分01秒 | 葵さんが下書き第3版、10,000円を承認 |
| 10時00分02秒 | 登録要求を送信。操作IDは Q17 |
| 10時00分07秒 | 応答待ちがタイムアウト |
| 10時00分10秒 | 葵さんが同じ登録ボタンをもう一度押す |

**演習**　最後の時点で分かっていることと、まだ分からないことを各一つ書きます。「登録済み」「失敗」「確認中」のどれを画面に出しますか。

**解答例**　要求を送った記録はある。相手が登録を完了したかは不明なので「確認中」と表示する。Q17で登録先を照会し、登録済みなら既存の見積番号を返す。再送には、同じ操作IDを何度受けても登録先で一件だけ確定する仕組み（冪等性）が必要になる。登録先で照会も重複防止もできなければ、担当者が突き合わせるまで再送を保留する。

**確認問題**　承認後に数量を12台に変更したら？　承認を下書きの版と結び付け、第4版の金額を再確認する。Q17は第3版に対する操作なので、新しい承認には新しい操作IDを割り当てる。

## 4　改善したと言える証拠を選ぶ

同じ未使用の20問で二つの構成を試しました。「回答可能」16問は正しい金額と出典がそろえば成功。「保留すべき」4問は根拠不足を示して金額を出さなければ成功です。以下は教材用の仮想結果です。

| 構成 | 回答可能で成功 | 保留すべき場面で成功 | 20問の推論費用 |
| --- | ---: | ---: | ---: |
| 現行 | 13/16 | 4/4 | 40円 |
| 候補 | 16/16 | 2/4 | 60円 |

**演習**　総合成功率と1問当たりの費用を計算します。営業責任者が「根拠がない金額を出したら自動提示は見送る」と決めていた場合、候補を導入しますか。

**解答例**　現行は17/20で85%、2円。候補は18/20で90%、3円。候補は根拠不足の2件で金額を提示したため、自動提示を見送る。その2件で検索対象、取得文書、生成結果を照合し、原因に対応する修正を一つ試す。修正に使った2件は回帰テストに残し、採用判定には別の未使用例を用意する。現行の4/4も、今後必ず保留できるという保証にはならない。

## 5　混雑時の挙動と導入条件を決める

昼休み明けに30件が同時に届きます。演習ではモデル呼び出しを同時に3件まで、所要時間を各6秒、1案件につき1回とします。他の処理にかかる時間は無視します。

**演習**　最後の案件が終わるまで何秒かかりますか。営業担当が画面を閉じても結果を受け取れる設計を考えてください。

**解答例**　3件ずつ10回処理するので60秒。受付時に依頼IDを返し、処理待ちの依頼を保存する。担当者が画面を開き直したら同じIDで進捗と結果を表示する。受付から処理開始までの待ち時間と、モデルの処理時間を別々に記録すれば、遅延がどちらで増えたか判断できる。この設計では受付は早くなるが、最後の案件の処理完了には依然60秒かかる。

### 仕上げの設計メモ

自分の業務を一つ選び、下の四行を埋めてください。第三者が「どの記録を見ればその判断を検証できるか」を答えられれば完成です。

1. 利用者が＿＿を終えるまでの＿＿を、現行手順と比較する。
2. AIには＿＿を渡す。根拠が＿＿のときは＿＿と表示する。
3. ＿＿の実行には承認を求める。応答が途切れたら＿＿で結果を確認する。
4. 試験導入の条件は＿＿。＿＿が起きたら自動処理を止め、＿＿に戻す。
